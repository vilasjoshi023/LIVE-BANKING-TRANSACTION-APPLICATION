# 17 November 2026 – Cassandra Commit Log Archiving Preparation

## Objective
Prepare a safe Commit Log archival integration for the VJCLAB Cassandra 4.1.12 cluster without changing live database configuration.

## Environment
- VJC9LAB1: 192.168.62.134
- VJC9LAB2: 192.168.62.135
- VJC9LAB3: 192.168.62.136
- Cassandra version confirmed by the operator as 4.1.12 on all three nodes.
- Cluster: VJCLAB, datacenter dc1.

## Activities performed
- Verified cluster status in the latest supplied `nodetool status` output: all three nodes were UN.
- Audited archive directory layout and ownership. Correct node-specific directories exist under `/var/backups/cassandra/archive/VJCLAB/`.
- Reviewed the Commit Log archiving properties file on all nodes. `archive_command`, `restore_command`, `restore_directories`, `restore_point_in_time` and `snapshot_commitlog_position` remain empty; precision is MICROSECONDS.
- Developed Commit Log archive script v2.0 at `/usr/local/bin/cassandra_commitlog_archive.sh`. It checks inputs, confirms source name, checks destination state, copies to a temporary file, compares source and copy, moves the copy into place, and logs operations.
- Deployed v2.0 to all three nodes. Syntax validation passed and the reported SHA-256 was identical across nodes: `41afc48d5300d27cbb573d06230fa995879684b9cc2566835b708b9d879c2857`.
- Tested dummy archive files on LAB1, LAB2 and LAB3. LAB2 and LAB3 integrity checks passed; LAB1 duplicate, conflict, missing-source and invalid-destination branches were exercised. A fresh successful v2 copy path has not yet been confirmed.
- Reviewed Cassandra 4.1.12 archive callback details as a design activity. Exact error/retry semantics still require validation against the matching version source before production-like integration.

## Results and validation
- Script deployment and dummy-file tests completed on all three nodes.
- No real Commit Log segment was archived.
- No Cassandra configuration was modified and no service was restarted.
- Current script has a potential no-overwrite race between the destination existence check and `mv`; hardening is required before integration.
- Temporary dummy files and placeholder directories remain and should be reviewed before cleanup. No cleanup was performed.

## Status

- In progress: authoritative callback semantics review, no-clobber hardening, fresh v2 copy test, failure/reconciliation strategy, PITR design.
- Deferred: live `archive_command` activation, restore configuration, service restart, real Commit Log file operations.
